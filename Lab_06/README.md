## 4. Результати 7 лабораторних експериментів

1. **Експеримент 1 (Слабкі vs Сильні тести):**  
   Слабкий тест без суворих `assert` показав $0.0\%$ виявлення внесеної мутації бізнес-логіки (інверсія знаку операції поповнення). Сильний тест виявив $100.0\%$ дефектів та зафіксував некоректний виклик сповіщувача.
2. **Експеримент 2 (Покриття без тверджень):**  
   Виконання коду забезпечило $100\%$ лінійного покриття рядків, проте відсутність тверджень проігнорувала критичний баг несанкціонованого овердрафту. Тест із `pytest.raises(InsufficientFundsError)` усунув дефект.
3. **Експеримент 3 (Аналіз розгалужень):**  
   Один тестовий випадок покриває лише $25\%$ логічних переходів методу `classify_tier`. Параметризований набір тестів перевірив усі 5 можливих станів балансу ($100\%$ branch coverage).
4. **Експеримент 4 (Mock vs Fake):**  
   Mock-об'єкт виконав $2000$ операцій за $48.57$ мс ($24.28$ мкс/оп), забезпечивши верифікацію інтерфейсу викликів. Fake-репозиторій виконав операції за $26.07$ мс ($13.03$ мкс/оп), дозволивши верифікувати реальний стан збережених об'єктів.
5. **Експеримент 5 (Flaky-тести vs Детерміновані):**  
   Використання системного часу призводить до періодичних відмов тесту в нічні години (стабільність $95.0\%$). Впровадження фіксованого часу через параметр функції забезпечило $100.0\%$ передбачуваність.
6. **Експеримент 6 (Ізоляція файлової системи):**  
   Спільний статичний файл спричиняє колізії при паралельному тестуванні ($85\%$ ризику взаємного блокування). Фікстура `tmp_path` гарантує $0.0\%$ колізій завдяки ізольованим тимчасовим каталогам для кожного тесту.
7. **Експеримент 7 (Сценарії відмови side_effect):**  
   Використання `mock_notifier.notify.side_effect = NotificationDeliveryError(...)` підтвердило здатність банківського сервісу перехоплювати відмови сторонніх шлюзів без порушення транзакційної цілісності.

## 6. Інструкція із запуску тестів

```bash
# 1. Запуск повного набору тестів з детальним виведенням
python -m pytest tests -v

# 2. Запуск з аналізом покриття коду та розгалужень
python -m pytest tests --cov=reliable_importer --cov-branch --cov-report=term-missing

# 3. Генерація інтерактивного HTML звіту покриття
python -m pytest tests --cov=reliable_importer --cov-branch --cov-report=html:htmlcov

# 4. Перевірка статичної типізації mypy
python -m mypy src tests

# 5. Перевірка відповідності стандарту PEP 8
python -m flake8 src tests

# 6. Запуск вимірювання числових метрик експериментів
python run_experiments_metrics.py
```
